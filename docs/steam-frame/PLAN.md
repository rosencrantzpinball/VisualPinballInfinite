# Visual Pinball Infinite on the Steam Frame: plan

The player (`vpi-player`) running on the Valve Steam Frame in VR: Linux arm64, SDL_GPU on Vulkan, OpenXR through SteamVR.
Progress, test recipes and run logs are in [PROGRESS.md](PROGRESS.md).

## The fork's lessons, and what each means for VPI

| Lesson (fork doc) | For VPI |
|---|---|
| SteamVR 2.17 allows one OpenXR instance, device and session per process: a second session crashed in `xrEndFrame` (Branch §10) | One XR session per player process; switching tables restarts the player |
| Turnip read textures as black from descriptor pools made with `FREE_DESCRIPTOR_SET_BIT` (Branch §7) | SDL 3.4.18 creates its pools with no flags (`SDL_gpu_vulkan.c` ~3797): not affected |
| Request only the Vulkan extensions the driver has (Branch §7) | Extra extensions go through `SDL_GPUVulkanOptions` only when present |
| `TU_AUTOTUNE_ALGO=profiled` before the driver loads: 14.0 → 9.1 ms (Foveated §7) | Set at start-up unless the user set it |
| The desktop mirror cost 4.5–6.6 ms, and presenting any desktop window into gamescope's 60 Hz Xwayland stalled the 72 Hz headset frame (Performance §6, §7.6) | In VR no window swapchain is presented at all |
| Unworn, SteamVR says `shouldRender = false`; the runtime's GPU counter reads 0.18 ms then (Performance §2.1) | Test mode renders anyway with pinned eyes; measurements wait for real frames |
| The Frame renders 1:1 with no anti-aliasing: sub-pixel lines crawl, chrome sparkles. Standard FXAA +1.6–2.5 ms is the only AA within budget; MSAA 4× +11 ms; specular AA costs nothing (Image Quality) | M4: FXAA by default in VR, specular AA in `material.hlsl`, MSAA off |
| Dynamic resolution: render into the top left of fixed buffers, submit `imageRect`, steer by `XR_META_performance_metrics` GPU time, target 85 %, floor 70 %, budget = shortest predicted period, hold readings in the stall band (Image Quality §8, Performance §7.5) | M4, same controller and log line every 5 s |
| Foveation that pays on Turnip is a `VK_KHR_fragment_shading_rate` attachment (8×8 texels, one layer for both eyes), not a density map (forces tiling); gaze from `XR_EXT_eye_gaze_interaction` (orientation only), eye tracker turned on by an eye-tracked `XR_FB_foveation` profile at level NONE; create the image empty, then update (Foveated §11) | M4, through a fourth SDL addition (render pass 2 with a rate attachment) |
| Disable the runtime's performance counters before the session ends (SteamVR crash) (Branch §9) | Done in the session teardown |
| Heat: 2–3 ms slower when hot; rest between measured runs; record temperatures (Image Quality §6.3, Performance §5) | The harness logs temperatures and spaces runs |
| The Frame sleeps a few minutes after the last run; the Steam dashboard opens over Non-Steam games at launch (Performance §9, README) | The harness keeps gaps short and reports when the dashboard holds focus |
| A `<table>.ini` beside the `.vpx` overrides `[PlayerVR]` (`ResFactor` = fraction of 8192 px, `Foveation` 0–3) (owner's notes) | M4: same keys, same file |
| The table's VR room must write depth; passthrough shows where nothing did (owner's notes) | Same rule with alpha from depth |
| Shared ROM folder `Tables/pinmame`, `alias.txt` with LF only (owner's notes) | M5, with the PinMAME host on Linux |

## Milestones

- **M0** this plan.
- **M1** flat on Linux: the player builds for arm64 in the image (SDL_GPU on Vulkan, SPIR-V shaders, libwinevbs for Linux), plays Symphony IX in a window on Xvfb with lavapipe, and its picture is compared with VPX's (the Linux VPX build the Symphony IX runner uses).
- **M2** VR: an OpenXR session drawing both eyes with VPX's table placement, the controllers mapped as the fork's, passthrough; checked first under Monado headless when it helps.
- **M3** on the Frame: a launch script under `SteamLinuxRuntime_4-arm64`, a package installed with Valve's devkit scripts under its own game id, the automated VR and headless runs passing.
- **M4** quality and speed: dynamic resolution, eye-tracked foveation, the AA choices, per-table `[PlayerVR]`, the perf line every 5 s.
- **M5** beyond Symphony IX: ROM tables (PinMAME host on Linux, shared ROM folder) once ROMs are supplied, the B2S backglass in VR, FlexDMD, an in-headset table picker.

## Risks

| Risk | Mitigation |
|---|---|
| HLSL written for FXC may not compile with DXC, or lay out differently (cbuffer packing, stage I/O locations, separate samplers) | Compile every entry point at build time and check the SPIR-V bindings and uniform offsets against FXC's layout; fix the HLSL so both compilers agree |
| Windows-only code throughout the player (COM/OLE glue, GDI text, DXGI vblank, the registry, named shared memory, crash reports) | `cfg` each one with a Linux path or a stub, keeping the Windows code untouched; Windows builds can't be run here, so the changes stay additive |
| SDL_GPU's Vulkan backend on Turnip, and our SDL additions | Small, marked patches like the existing ones; test on lavapipe first, then on the Frame |
| Drawing each eye separately doubles the CPU's draw submission | Measure on the Frame; multiview later if needed |
| The player's cost at 1920–2160² per eye with no foveation before M4 | Start below native (the runtime's recommended size), then M4 |
| Remote VR runs: the dashboard at launch, `shouldRender` false unworn, sleep | Forced rendering in test mode, timeouts, logs of the session state |
| The Mac's system disk (≈16 GB free) holds OrbStack's images | One lean image; everything else on `/Volumes/storage`; check `df -h /` before big steps, stop under 5 GB |
